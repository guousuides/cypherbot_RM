# rm-slack-bot

RM定例の「議事録リンク・Meetリンク・本日の進行担当（主担当/副担当）」を、毎週月・木にSlackへ自動投稿するボットです。

- 実行環境は **GitHub Actions**（サーバー不要・無料枠）。特定の個人のPCやアカウントの常時稼働に依存しません。
- 議事録URL・Meet URLは固定値（GitHub Secrets）を使い回します。
- 本日の主担当/副担当は、当番表のGoogleスプレッドシートを毎回読みに行きます。**スプレッドシートを編集するだけで反映され、GitHubは触らなくてOKです。**

## ファイル構成

| ファイル | 役割 |
|---|---|
| `.github/workflows/post-rm.yml` | 実行スケジュールと、実行時に渡す環境変数の定義 |
| `post-rm-message.js` | メッセージ（Slack Block Kit）を組み立てて投稿する本体 |
| `members.json` | 当番表の名前 → SlackメンバーID の対応表 |
| `package.json` | 依存ライブラリ（`@slack/web-api`）の定義 |

---

## 1. Slack Appの準備（初回のみ）

1. https://api.slack.com/apps →「Create New App」→「From scratch」（または Blank app）
2. App名と、**投稿先チャンネルがあるワークスペース**を選ぶ（後から変更できません）
3. 「OAuth & Permissions」→「Bot Token Scopes」に `chat:write` を追加
4. 「Install to Workspace」（既にあれば「Reinstall」）で許可
5. 「Bot User OAuth Token」（`xoxb-` で始まる文字列）をコピー → `SLACK_BOT_TOKEN` に使います
6. 投稿先チャンネルでボットを追加（チャンネル名をクリック →「インテグレーション」→「アプリを追加」）

### チャンネルIDの調べ方
チャンネル名をクリック → 一番下までスクロール、または「リンクをコピー」。
`https://xxx.slack.com/archives/C0XXXXXXXXX` の `C0XXXXXXXXX` がチャンネルIDです。

### SlackメンバーIDの調べ方
メンバーのプロフィールを開く →「…」→「メンバーIDをコピーする」。`U` で始まる文字列です。

## 2. 当番表（Googleスプレッドシート）をCSVで公開する

1. 当番表のスプレッドシートを開く（当番表のタブを表示した状態で）
2. 「ファイル」→「共有」→「ウェブに公開」
3. 1つ目のプルダウンは「ブック全体」ではなく**当番表のシート（タブ）**を選ぶ
4. 2つ目のプルダウンは**「カンマ区切りの値（.csv）」**を選ぶ（「ウェブページ」のままだと使えません）
5. 「公開」→ OK
6. 発行されたURL（`https://docs.google.com/spreadsheets/d/e/2PACX-.../pub?...output=csv` の形）をコピー → `SCHEDULE_CSV_URL` に使います

注意:
- 編集画面のURL（`.../edit?...`）や、`.../pubhtml` で終わるURLは使えません（HTMLが返るため読み取れません）。`pubhtml` の部分を `pub?output=csv` に書き換えても使えます。
- 「ウェブに公開」は、リンクを知っている人なら誰でも読める状態になります。当番表には日付と担当者名しか入れない前提です。

### 当番表の列
次の見出しを含む列があれば、列の順番は問いません（部分一致）。

| 見出し | 内容 |
|---|---|
| 日付 | 例: `10/1`、`10月1日`、`2026/10/1`、`2026-10-01`、`2026年10月1日` |
| 主担当 | その日の主担当の名前 |
| 副担当 | その日の副担当の名前 |

年が省略された日付（`10/1` など）は、実行時点の日本時間の年として扱います。当番表が年をまたぐ場合だけ、該当の行に年を書いてください。

### 名前とSlack IDの対応（`members.json`）
```json
{
  "布施": "U01ABCDEF2",
  "郭": "U01ABCDEF3"
}
```
- キーは当番表の主担当/副担当セルの表記と一致させてください（末尾の「さん」「様」は自動で無視します）。
- 未登録の名前は、メンションされず名前だけ表示されます（投稿は失敗しません）。
- メンバーの入れ替わりがあったときだけ、GitHub上でこのファイルを編集します。

## 3. GitHub Secretsの設定

リポジトリの Settings → Secrets and variables → Actions → **Secrets** タブに登録します（Variablesタブではありません）。

| Secret名 | 値 |
|---|---|
| `SLACK_BOT_TOKEN` | Bot User OAuth Token（`xoxb-...`）。**これだけが機密情報** |
| `RM_CHANNEL_ID` | 投稿先チャンネルID（`C...`） |
| `MINUTES_URL` | 議事録のGoogleドキュメントURL（固定） |
| `MEET_URL` | Google MeetのURL（固定） |
| `SCHEDULE_CSV_URL` | 手順2で発行した当番表の公開CSVのURL |

名前は一字一句この通りにしてください（例: `SLACK_BOTTOKEN` のような綴り違いだと「環境変数が設定されていません」と出ます）。

`SCHEDULE_CSV_URL` が未設定でも、進行担当の行が出ないだけで投稿は動きます。

## 4. 動作確認（dry run）

実際には投稿せず、投稿内容だけをログで確認できます。

1. リポジトリの「Actions」タブ → 左のワークフロー名 → 右上「Run workflow」
2. **`dry_run` にチェックを入れて**実行
3. 実行をクリック → ジョブ「post」→ ステップ「Run node post-rm-message.js」を開く
4. 「=== DRY RUN ===」の下に、投稿予定のメッセージ（JSON）が出ます

チェックを外して実行すると、実際にSlackへ投稿されます。

ログのメッセージの意味:

| ログ | 意味 |
|---|---|
| `本日(...)の担当が当番表から見つかりませんでした (reason: no-match)` | 今日の日付の行が当番表にない（期間外など）。投稿自体は行われます |
| `CSVではなくHTMLが返ってきました` | `SCHEDULE_CSV_URL` が公開CSVのURLになっていない |
| `当番表のヘッダー(...)が見つかりませんでした` | 見出し行に「日付/主担当/副担当」がない。取得できた1行目がログに出ます |
| `(Slack ID未登録)` と表示される | `members.json` にその名前がない |

## 5. 配信スケジュール

`.github/workflows/post-rm.yml` の `cron` で指定します。**UTC基準**なので、日本時間から9時間引いた値を書きます。

```yaml
- cron: '7 4 * * 1,4'   # 毎週 月・木 13:07 JST（= 04:07 UTC）
```

- 書式: `分 時 * * 曜日`（0=日, 1=月, ..., 6=土。カンマ区切りで複数可）
- 1日に複数回: `'7 1,3,6 * * *'`（毎日 10:07, 12:07, 15:07 JST）
- 分を0にしていないのは、毎時00分にGitHub側の実行が集中して遅延しやすいためです。

### 既知の制限（重要）
GitHub Actionsのスケジュール実行は、**指定時刻ぴったりに実行される保証がありません**。混雑時に数時間遅れることがあり、実際に13:07指定が19:52に実行された例がありました。時刻の正確さが必要な場合は、外部のcronサービスからGitHub APIの `workflow_dispatch` を呼び出す方式に切り替えてください（コード側の変更は不要です）。

## 6. 引き継ぎ

- 実行環境はGitHub Actionsだけです。サーバーはありません。
- Secretsを管理できるのはリポジトリのオーナーだけです（個人アカウントのリポジトリの場合）。引き継ぐときは、Settings → General → 一番下の「Transfer ownership」でリポジトリごと譲渡するか、引き継ぎ先のアカウントでリポジトリを作り直してコードを移し、Secretsを登録し直してください。
- Slack Appの管理は https://api.slack.com/apps から行います。引き継ぎ先の人を「Collaborator」に追加すると、その人がトークンの確認・再発行をできます。
- トークンの値をチャットやメールに平文で貼らないでください。引き継ぎ時はトークンを再発行し、受け取った人が自分でSecretsに登録するのが安全です。
- 日々の運用（当番表の更新）はスプレッドシートの編集だけで完結します。
